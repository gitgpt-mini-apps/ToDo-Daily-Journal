e-Bullet Journal README / 使い方

対象: "index.html"
公開方式: GitHub Pages
確認日: 2026-10-01

1. 起動・データの保存

1. GitHub Pagesで公開されたURLをChromeなどのブラウザで開きます。
2. スマートフォン・PCなど、ブラウザが利用できる端末からアクセスできます。
3. ホーム画面への追加機能が利用できる場合は、ブラウザのメニューからホーム画面に追加できます。
4. アプリのデータは、利用しているブラウザの"localStorage"に保存されます。通常の利用において、データを保存するためのサーバー接続は必要ありません。
5. データはブラウザ・端末ごとに保存されます。同じ公開URLを別の端末で開いても、自動的には同期されません。
6. ブラウザのサイトデータを削除した場合など、保存したデータが失われることがあります。定期的にJSONバックアップを保存してください。

公開サイトとデータの取り扱い

- GitHub Pagesはアプリ本体を公開するための仕組みです。公開サイトを利用する人が、同じタスクや記録を自動的に共有するわけではありません。
- 各利用者は、自分のブラウザにデータを保存して独立して利用できます。
- データの保存先はブラウザの"localStorage"です。Google DriveやOneDriveなどを介した自動同期機能は、現行版では実装されていません。
- GitHub上で公開されるのはリポジトリ内のファイルです。ブラウザ内に保存されたデータが、それだけでGitHubにアップロードされることはありません。

2. 画面を切り替える

- 上部または下部のFuture／Monthly／Daily／ToDoをタップします。
- スマートフォンでは、画面下部のタブ直上にある帯を左右にスワイプしても隣の画面へ移動できます。
- 下部タブは画面切替にも使え、現在の画面が強調表示されます。

3. 4画面の使い分け

Future

年間を2か月ずつ見渡す画面です。

- カード右上の「＋」から予定を作成します。
- 作成した予定はMonthlyとToDoにも表示されます。
- 横スクロールで年内の月を移動します。

Monthly

1か月の日別カードを確認する画面です。

- カードの「＋」から、その日を予定日とするタスクを作成します。
- Monthlyで作成した予定はToDoにも表示されます。

Daily

1日ごとの記録・実行状況を管理する画面です。

- カードの「＋」から、その日の記録を作成します。
- 上部の「未完了ToDoをDailyに転記」欄から予定を選んで記録を作成できます。タスクを選ばず、新規作成することもできます。
- Daily記録はToDoにも連動項目を作成します。
- Dailyで新規作成した項目は、Monthlyには表示されません。

ToDo

完了・中止以外の予定を予定日順に確認する画面です。

- 当日以前の予定は色で強調されます。
- タスクを選択すると、タイトル・日付・時刻・メモを編集できます。
- 状態の更新はDailyから行います。

4. タスクの作成・編集

1. Future、Monthly、Dailyのカードにある「＋」を押します。
2. タイトルと日付を入力します。時刻は任意です。
3. Dailyの記録では、状態（未実施／未着手／着手／完了／延期／中止）を選択できます。
4. 延期の場合は、延期後の日付も入力します。
5. Daily記録のメモは、ルーティン以外の項目で利用できます。
6. 保存後、カードのタスク行を選択すると編集できます。変更後は「保存」を押します。
7. Future／Monthlyの予定をDailyに別途作成する場合は、予定タスクを開き「Dailyへ作成」を押して記録日を選び、保存します。

注意: Future／Monthlyの予定から「Dailyへ作成」で作成した項目は、元の予定とは別の項目です。作成後にDaily側で編集しても、元の予定には反映されません。

5. DailyとToDoの連動

- Dailyで未完了ToDoを選んで記録を作成すると、そのToDoとDaily記録が連動します。
- Daily記録からタイトル・メモ・時刻・状態を変更すると、連動するToDoにも反映されます。
- 「着手」または「未着手」の項目は、翌日に未実施として引き継ぐ処理があります。
- 完了や状態変更に応じて、引継ぎ項目が整理されます。
- Dailyで独自に作成した項目は、ToDoにも連動する予定を作成します。Monthlyには表示されません。
- Future／Monthlyの予定から「Dailyへ作成」で転記した項目は、通常のToDoから転記した項目とは異なり、元予定との連動はありません。

6. 月・年の移動と横スクロール

- Future／Dailyは画面内を横スクロールできます。
- 通常の縦ホイールを横スクロールに変換する処理はありません。
- マウスではShiftキーを押しながらホイールを回す、横スクロール対応ホイールを使うなど、ブラウザが横入力として認識する操作が使えます。
- トラックパッドでは横方向の指操作が使えます。
- 月／年の選択は下部の期間フッターでもできます。
- Future／Dailyで端に達した後、さらに同じ方向へ横入力すると次の年／月へ移動します。端に到達しただけでは切り替わりません。
- Monthlyはカードを縦に並べ、フッターで月を選びます。

7. ワークスペース

共通メニュー（左上の☰）

- 新しいタブ名を入力して「タブを追加」します。
- 一覧から名前の変更や削除ができます。
- 最後のワークスペースは削除できません。
- 開始年月とFuture／Monthly／Daily／ToDoの色を設定します。これらは全ワークスペース共通です。
- 「すべてのデータをクリア」は全ワークスペースを初期化します。実行前に必要なJSONバックアップを保存してください。

ワークスペース設定（右上の歯車）

- ルーティンの追加・編集・削除を行います。
- JSONバックアップ／復元を行います。操作対象は現在選択中のワークスペースです。
- 「このワークスペースのデータを消去」は、現在のワークスペースだけを初期化します。

8. ルーティン

1. 右上の歯車を開きます。
2. 内容、毎日／毎週、必要に応じて曜日、開始日、終了日を設定して「登録」します。
3. 終了日を空欄にすると、開始月末が終了日の初期値になります。
4. 登録期間中の日付にDaily項目が自動生成されます。
5. 休みなどで不要な日を削除すると、その日の生成をスキップします。
6. ルーティン定義を削除しても、既に作成された過去の記録は残ります。

9. バックアップと復元

バックアップ

1. 右上の歯車を開きます。
2. 「JSONを保存」を選択します。
3. 現在のワークスペースのデータをJSONファイルに書き出します。
4. ファイル名にはワークスペース名と保存日が含まれます。

復元

1. 復元先のワークスペースを選択します。
2. 右上の歯車を開き、「JSONを読み込む」を選択します。
3. バックアップファイルを指定します。

注意: 読み込み先の現在のワークスペースのデータは、読み込んだデータに置き換わります。必要に応じて、復元前に現在のデータもバックアップしてください。

バックアップが必要な場面

- ブラウザのサイトデータを削除する前
- 端末やブラウザを変更する前
- データを復元する前
- 重要な記録を追加・変更した後

JSONバックアップは、別の端末へのデータ移行にも利用できます。

10. 現行版の注意事項

- 新規データの開始年月は、アプリを初めて開いた時点の年月です。固定値ではありません。必要に応じて共通メニューで変更してください。
- Future／Monthlyの予定を「Dailyへ作成」で転記した場合、独立したDaily項目になります。Dailyでの後編集を元予定へ同期する仕様は未実装です。
- ToDoからDailyに転記した項目は連動します。
- データはブラウザの"localStorage"に保存されます。同じ公開サイトでも、別の端末やブラウザではデータが自動共有されません。
- ブラウザのサイトデータ削除やブラウザ環境の変更によって、保存データが見えなくなることがあります。JSONを定期的に保存してください。
- GitHub Pagesで公開されたアプリ本体を更新しても、ブラウザ内の保存データが別の端末へ自動移行するわけではありません。
- 公開URLやアプリの動作に変更があった場合は、最新版のREADMEと実際の画面を確認してください。
